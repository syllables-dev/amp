# @syllables-dev/amp

Typed client for the Apple Music web player API at `amp-api.music.apple.com`.

## Layout

- `src/client/` builds the public client. `index.ts` assembles it from `context.ts` (transport, storefront, language and shared lookups) and one module per area: `catalog.ts`, `library.ts`, `search.ts`, `charts.ts` and the raw `request.ts`. Option types live in `options.ts`.
- `src/types.ts` holds resource attribute types and the `Registry` that maps each resource type to its relationships, defaults, extends and views. Attribute types come from captured live responses, not the spec.
- `src/generated/operations.ts` is generated by `bun run generate` from `../docs/content/docs/musickit/amp-api.yaml`. Never edit it by hand.
- `src/limits.ts` holds Apple's `limit` cap per relationship and view. The types read it, so a `limit` above the cap does not compile.
- `src/internal/` holds the transport (headers, cache, in-flight dedupe, errors), the batcher, hydration and pagination.

## Behavior to preserve

- Every request asks for `format[resources]=map`. Hydration turns the map into plain objects and cuts cycles with `{ id, type, href }` stubs, so results stay JSON-serializable.
- Catalog `get` without `views` goes through the batcher, which merges same-tick gets into one multi-fetch. A batched id that is absent from the response is a 404, never another resource.
- `next` links drop the original query, so pagination merges the original query with the cursor from `next`.
- `Registry` in `src/types.ts` drives every result type. Per type: `attributes` (always sent; optional only when Apple sometimes omits it), `extended` (only with `extend`), `refs` (bare references sent by default), `defaults` (full objects sent by default), `optional` (may be absent even when included), `partial` (included items may be bare references), `singleOnly` (library includes Apple rejects on list calls) and `views` (view name to item type).
- Change the registry only after confirming against live responses with `bun run audit`. Never mark an attribute required unless every sampled response had it.
- `get` completes capped relationships through `src/internal/complete.ts`, following `next` at the cap in `src/limits.ts`, unless `complete: false`. Probe a cap with growing `limit` values until Apple answers 400 before changing `src/limits.ts`.
- Batched gets respect Apple's per-type id limits in `src/internal/batcher.ts` (songs and genres 300, artists and playlists 50, others 100).

## Rules

- Always use the Bun toolchain: `bun` and `bunx`. Never `node`, `npm`, `pnpm`, or `npx`.
- Do not use em dashes anywhere.
- Zero runtime dependencies.
- Named exports only. Import through the `@/` alias.
- Do not set `sideEffects: false` in package.json: Bun's bundler then drops re-exported modules and emits an empty `dist/index.js`.
- No SCREAMING_SNAKE_CASE. Settings live in `src/config.ts`, fixed limits stay inline.
- Do not add comments. Lint suppressions are the exception.
- No `any`. Keep `as` casts at the JSON and generic boundaries only.
- `tests/fixtures/` holds public catalog responses only. Never commit library or account responses.

## Code quality

After any change:

1. `bun tsgo`
2. `bun fix`
3. `bun test`

Type-level behavior is tested in `tests/types.test.ts` with `expectTypeOf` and `@ts-expect-error`; tsgo checks it.

Rerun until all three pass in the same round.
