# @syllables-dev/amp

Typed client for the Apple Music web player API at `amp-api.music.apple.com`.

## Layout

- `src/client/` builds the public client. `index.ts` assembles it from `context.ts` (transport, storefront, language and shared lookups) and one module per area: `catalog.ts`, `library.ts`, `search.ts`, `charts.ts`, `recommendations.ts` and the raw `request.ts`. Option types live in `options.ts`.
- `src/types/` holds the response types. `resources/` has one file per resource type with its attributes, extends, views and registry entry (`AlbumsEntry`). `registry.ts` assembles the `Registry` from those entries, `resource.ts` holds the generic result types (`Resource`, `Ref`, `Page`) and `common.ts` holds shapes shared across resources. Attribute types come from captured live responses, not the spec. A type used by one resource lives in that resource's file.
- `src/generated/operations.ts` is generated by `bun run generate` from `../docs/content/docs/musickit/amp-api.yaml`. Never edit it by hand.
- `src/cities.ts` holds the cities, as 4-character geohashes, that the web player's concerts hub falls back to per storefront when it has no visitor location. Pass one as `geoHash` for nearby concerts.
- `src/limits.ts` holds Apple's `limit` cap per relationship and view. The types read it, so a `limit` above the cap does not compile.
- `src/internal/` holds the transport (headers, cache, in-flight dedupe, errors), the batcher, hydration and pagination.

## Behavior to preserve

- Every request asks for `format[resources]=map` and `platform=web`. Without a platform Apple drops every resource from a multi-fetch that asks for an editorial extend such as `plainEditorialCard`. Hydration turns the map into plain objects and cuts cycles with `{ id, type, href }` stubs, so results stay JSON-serializable.
- Catalog `get` without `views` goes through the batcher, which merges same-tick gets into one multi-fetch. A batched id that is absent from the response is a 404, never another resource.
- `next` links drop the original query, so pagination merges the original query with the cursor from `next`.
- `Registry` in `src/types/registry.ts` drives every result type, through the entry in each `src/types/resources/` file. Per type: `attributes` (always sent; optional only when Apple sometimes omits it), `extended` (only with `extend`), `refs` (bare references sent by default), `defaults` (full objects sent by default), `embedded` (relationships Apple still sends when the resource is itself included, which `defaults` are not), `optional` (may be absent even when included), `partial` (included items may be bare references), `singleOnly` (library includes Apple rejects on list calls) and `views` (view name to item type).
- Change the registry only after confirming against live responses with `bun run audit`. Never mark an attribute required unless every sampled response had it.
- `get` completes capped relationships through `src/internal/complete.ts`, following `next` at the cap in `src/limits.ts`, unless `complete: false`. Without a `meta.total`, album and playlist `trackCount` sets the total so the remaining pages load in parallel. Playlist gets add `trackCount` to `extend` for this and strip it from the result unless it was asked for. `trackCount` can overcount, so a 404 past the end counts as an empty page, and a `next` left on the last page is still followed. Probe a cap with growing `limit` values until Apple answers 400 before changing `src/limits.ts`.
- Batched gets respect Apple's per-type id limits in `src/internal/batcher.ts` (songs and genres 300, artists, concerts and playlists 50, others 100).

## Rules

- Always use the Bun toolchain: `bun` and `bunx`. Never `node`, `npm`, `pnpm`, or `npx`.
- Do not use em dashes anywhere.
- Zero runtime dependencies.
- Named exports only. Import through the `@/` alias.
- Do not set `sideEffects: false` in package.json: Bun's bundler then drops re-exported modules and emits an empty `dist/index.js`.
- No SCREAMING_SNAKE_CASE. Settings live in `src/config.ts`, fixed limits stay inline.
- Do not add comments. Lint suppressions are the exception.
- No `any`. Keep `as` casts at the JSON and generic boundaries only.
- `tests/fixtures/` holds public catalog responses only. Never commit library or account responses.

## Code quality

After any change:

1. `bun tsgo`
2. `bun fix`
3. `bun test`

Runtime behavior is tested in `tests/client/`, one file per area, with the fake API in `tests/helpers.ts`. Type-level behavior is tested in `tests/types.test.ts` with `expectTypeOf` and `@ts-expect-error`; tsgo checks it.

Rerun until all three pass in the same round.
